1. 平台概述

A2A Platform 是一个基于 A2A (Agent-to-Agent) 协议 的主机控制平面（Host Control Plane）。 它为多个 AI Agent 提供统一的发现、通信、任务管理和追踪能力，使 Agent 之间可以透明地互相对话。

核心概念

  • Host（主机） — 本平台。负责 Agent 注册、消息路由、任务生命周期管理和调用追踪。
  • Agent（代理） — 任何实现了 A2A 协议的服务。通过 AgentCard 自描述，通过 JSON-RPC 接收消息。
  • AgentCard — Agent 的自描述文件，暴露在 /.well-known/agent.json，包含名称、技能、版本等信息。
  • Task（任务） — 一次 Agent 交互的完整生命周期，状态包括 SUBMITTED、WORKING、COMPLETED、FAILED 等。
  • SSE 事件流 — Agent 通过 Server-Sent Events 向 Host 实时推送任务状态更新和消息。
  • Trace（追踪） — 记录每次 Agent 交互的完整事件链，便于调试和审计。

2. 快速开始

2.1 环境要求

  • Go 1.25+
  • Git

2.2 构建并运行 Host

# 克隆仓库
git clone <repo-url> a2a_platform
cd a2a_platform

# 构建 Host 二进制文件
go build -o bin/host ./cmd/host

# 启动 Host（默认监听 0.0.0.0:7860）
./bin/host -f etc/host.yaml

启动成功后输出：

A2A Host started on 0.0.0.0:7860

2.3 验证服务

# 查看平台能力
curl http://localhost:7860/api/capabilities

# 查看已注册 Agent 列表（初始为空）
curl http://localhost:7860/api/agents

2.4 快捷命令（Makefile）

make host         # 直接运行 Host（开发模式）
make fake-agent   # 运行测试用 Fake Agent
make test         # 运行所有单元测试
make e2e          # 运行端到端测试
make clean        # 清理数据库和测试缓存

3. 配置说明

Host 的配置文件位于 etc/host.yaml，基于 go-zero 的 rest.RestConf 扩展。

配置示例

Host: "0.0.0.0"
Port: 7860
DataSource: "file:a2a_platform.db?cache=shared&_journal_mode=WAL"
Timeout: 30000
AgentRetryMax: 3
AgentRetryBaseDelay: 1
LogLevel: info

配置项说明

配置项 类型 默认值 说明
Host string 0.0.0.0 HTTP 监听地址
Port int 7860 HTTP 监听端口
DataSource string file:a2a_platform.db?cache=shared&_journal_mode=WAL SQLite 数据源连接字符串。支持 :memory: 用于测试。
Timeout int 30000 HTTP 请求超时（毫秒）
AgentRetryMax int 3 连接 Agent 时最大重试次数
AgentRetryBaseDelay int 1 重试基础延迟（秒），采用指数退避策略
LogLevel string info 日志级别：debug / info / error / severe
重试策略：Registry 连接 Agent 时，重试延迟为 baseDelay * 2^attempt。 默认配置下，三次重试的等待时间分别为 1s、2s、4s。

向指定 Agent 发送消息，通过 SSE 流式返回事件。

请求体：

字段类型必填说明
agent_namestring是目标 Agent 名称
messagestring是消息内容
context_idstring否上下文 ID，用于关联多轮对话

请求示例：

SSE 响应流：

data: {"type":"status_update","data":{"old_state":"SUBMITTED","new_state":"WORKING"}}

4.10 POST /agent/:name

SSE 代理端点。将请求透明转发到已连接的 Agent，支持路径和查询参数透传。

POST /agent/:name (SSE Proxy)

路径规则：

/agent/<name>              -> http://<agent-url>/
/agent/<name>/path        -> http://<agent-url>/path
/agent/<name>/path?q=1    -> http://<agent-url>/path?q=1

请求示例（发送 JSON-RPC 消息）：

curl -N -X POST http://localhost:7860/agent/weather-agent \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": "1",
    "method": "SendStreamingMessage",
    "params": {
      "message": {
        "role": "user",
        "parts": [{"kind": "text", "text": "Hello"}]
      }
    }
  }'

代理特性：

  • 自动注入 A2A-Version: 1.0 请求头（如未设置）
  • 自动剥离 Hop-by-Hop 头部（Connection、Keep-Alive、Transfer-Encoding 等）
  • 完整转发响应头和状态码
  • 支持 SSE 流式响应的实时转发
注意：Agent 必须已通过 /api/agents/register 注册且状态为 connected，否则返回 404。

5. Agent 接入

本平台支持三种 Agent 注册方式：

5.1 远程自动注册（推荐）

启动 Agent 服务后，调用注册接口，Host 自动拉取 AgentCard 并建立连接：

curl -X POST http://localhost:7860/api/agents/register \
  -H "Content-Type: application/json" \
  -d '{"url": "http://your-agent:8080"}'

Host 会自动完成以下步骤：

  1. 请求 http://your-agent:8080/.well-known/agent.json 获取 AgentCard
  2. 解析 Agent 名称、版本、技能等信息
  3. 将信息持久化到数据库
  4. 在内存中创建 A2A Client 连接
  5. 连接失败时自动重试（指数退避，最多 AgentRetryMax 次）

5.2 动态 API 注册

通过 POST /api/agents 接口注册，行为与远程注册相同：

curl -X POST http://localhost:7860/api/agents \
  -H "Content-Type: application/json" \
  -d '{"url": "http://your-agent:8080", "type": "custom"}'

5.3 直接数据库写入（高级）

通过 Registry 的 UpsertAgent 方法直接写入数据库。这种方式不会创建实时连接，适用于静态预配置场景。通常在测试或初始化脚本中使用。

最佳实践：生产环境推荐使用方式 1（远程自动注册）。Agent 服务启动后，在自身的健康检查或启动流程中调用 Host 注册接口。

6. Agent 开发

开发一个符合 A2A 协议的 Agent 需要实现两个核心端点：

6.1 AgentCard 端点

Agent 必须在 GET /.well-known/agent.json 返回自描述信息：

GET /.well-known/agent.json

{
  "name": "my-agent",
  "description": "A custom A2A agent that does X",
  "version": "1.0.0",
  "url": "http://my-agent:8080",
  "capabilities": {
    "streaming": true
  },
  "skills": [
    {
      "id": "skill-1",
      "name": "Translate",
      "description": "Translate text between languages",
      "tags": ["translation", "nlp"],
      "examples": ["Translate 'hello' to French"]
    }
  ],
  "supportedInterfaces": ["A2A/1.0"]
}

AgentCard 字段说明

字段类型必填说明
namestring是Agent 唯一标识名称
descriptionstring是Agent 功能描述
versionstring是语义版本号
urlstring是Agent 的基础 URL
capabilitiesobject是能力声明，streaming 表示是否支持 SSE
skillsarray否技能列表
supportedInterfacesarray否支持的接口版本

6.2 JSON-RPC 消息端点

Agent 必须在 POST / 接收 JSON-RPC 2.0 请求：

POST /
Content-Type: application/json
Accept: text/event-stream
A2A-Version: 1.0

{
  "jsonrpc": "2.0",
  "id": "1",
  "method": "SendStreamingMessage",
  "params": {
    "message": {
      "role": "user",
      "parts": [{"kind": "text", "text": "Hello, agent!"}]
    },
    "taskId": "optional-task-id",
    "contextId": "optional-context-id"
  }
}

6.3 SSE 流式响应

支持 SSE 的 Agent 应返回 Content-Type: text/event-stream：

HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

data: {"type":"status_update","data":{"state":"WORKING"}}

data: {"type":"message","data":{"role":"agent","parts":[{"kind":"text","text":"Hello! How can I help?"}]}}

data: {"type":"status_update","data":{"state":"COMPLETED"}}

6.4 最小 Agent 示例（Go）

package main

import (
    "encoding/json"
    "fmt"
    "net/http"
)

func main() {
    mux := http.NewServeMux()

    // AgentCard
    mux.HandleFunc("/.well-known/agent.json", func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json")
        json.NewEncoder(w).Encode(map[string]interface{}{
            "name":        "my-agent",
            "description": "My custom A2A agent",
            "version":     "1.0.0",
            "url":         "http://localhost:8080",
            "capabilities": map[string]bool{"streaming": true},
            "skills":      []map[string]string{
                {"id": "greet", "name": "Greet", "description": "Say hello"},
            },
        })
    })

    // JSON-RPC endpoint
    mux.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
        if r.Method != http.MethodPost {
            http.Error(w, "method not allowed", 405)
            return
        }

        var req map[string]interface{}
        json.NewDecoder(r.Body).Decode(&req)

        // SSE response
        w.Header().Set("Content-Type", "text/event-stream")
        w.Header().Set("Cache-Control", "no-cache")
        w.Header().Set("Connection", "keep-alive")

        event, _ := json.Marshal(map[string]interface{}{
            "type": "message",
            "data": map[string]interface{}{
                "role": "agent",
                "parts": []map[string]string{
                    {"kind": "text", "text": "Hello from my-agent!"},
                },
            },
        })
        w.Write([]byte("data: " + string(event) + "\n\n"))
        if f, ok := w.(http.Flusher); ok {
            f.Flush()
        }
    })

    fmt.Println("Agent running on :8080")
    http.ListenAndServe(":8080", mux)
}

7. SSE 事件格式

A2A 协议通过 Server-Sent Events (SSE) 实现实时通信。所有 SSE 事件的 data 字段为 JSON，包含 type 和 data 两个顶层字段。

7.1 事件类型总览

type 值 说明 触发时机
task 任务创建通知 Agent 创建或确认任务时
status_update 任务状态变更 Agent 开始/完成/暂停处理时
artifact_update 产物更新 Agent 产出文件、代码等结构化产物时
message 消息 Agent 发送文本回复时
response 最终响应（平台层） Host 整合所有事件后发出的最终响应

7.2 task 事件

data: {"type":"task","data":{"server_task_id":"abc-123","state":"SUBMITTED"}}
字段类型说明
data.server_task_idstringAgent 端的任务 ID
data.statestring任务初始状态

7.3 status_update 事件

data: {"type":"status_update","data":{"old_state":"SUBMITTED","new_state":"WORKING"}}
字段类型说明
data.old_statestring变更前状态（Host 记录）
data.new_statestring变更后状态

7.4 artifact_update 事件

data: {"type":"artifact_update","data":{"artifact":{"name":"generated_code","parts":[{"kind":"text","text":"function hello() {...}"}]}}}
字段类型说明
data.artifact.namestring产物名称
data.artifact.partsarray产物内容片段列表

7.5 message 事件

data: {"type":"message","data":{"role":"agent","text":"Hello! How can I help you?"}}
字段类型说明
data.rolestring消息角色：user 或 agent
data.textstring消息文本内容

7.6 SSE 线路格式

标准 SSE 格式，每条消息以 data: 开头，空行分隔：

data: {"type":"status_update","data":{"state":"WORKING"}}

data: {"type":"message","data":{"role":"agent","text":"Processing your request..."}}

data: {"type":"status_update","data":{"state":"COMPLETED"}}
SSE vs 非 SSE：如果 Agent 不支持 SSE，Host 也能处理普通的 JSON 响应。此时整个响应体会被包装为一个 type: "message" 事件。

8. Trace 追踪

Tracer 记录每次 Agent 交互的完整事件链，是调试和排错的利器。

8.1 追踪事件类型

事件类型说明数据字段
send 消息发送 {"content": "..."}
task_created 任务创建 {"server_task_id": "..."}
task_update 任务状态变更 {"old_state": "...", "new_state": "..."}
artifact 产物产出 {"text": "..."}
response Agent 响应 {"text": "...", "source": "agent-name"}
error 错误 {"error": "..."}

8.2 查看 Trace

使用 GET /api/tasks/:id/trace 获取纯文本格式的调试追踪：

# 先获取任务列表，找到 task ID
curl http://localhost:7860/api/tasks

# 查看追踪
curl http://localhost:7860/api/tasks/task_20260514_001/trace

输出示例：

[send] content="What is the weather?" agent="weather-agent"
[task_created] server_task_id="abc-123"
[task_update] SUBMITTED -> WORKING
[artifact] text="Weather data: 25C, sunny"
[response] text="Weather data: 25C, sunny" source="weather-agent"

8.3 完整调试流程

# 1. 发送消息并记录 Task ID
curl -N -X POST http://localhost:7860/api/chat \
  -H "Content-Type: application/json" \
  -d '{"agent_name": "weather-agent", "message": "Weather?"}'

# 响应中会包含 local_task_id，例如 "task_001"

# 2. 查看任务状态
curl http://localhost:7860/api/tasks?agent_name=weather-agent

# 3. 如果任务失败，查看完整追踪
curl http://localhost:7860/api/tasks/task_001/trace

9.4 Fake Agent

平台内置测试用 Fake Agent，支持 12+ 种行为模式，用于模拟各种 Agent 响应场景：

模式说明
echo回显输入文本（默认模式）
sequence返回有序事件序列：WORKING -> message -> COMPLETED
artifact返回产物事件：WORKING -> artifact -> COMPLETED
json_response返回普通 JSON（非 SSE），SSE 请求时回退到 echo
record_headers记录并返回所有请求头（用于验证头注入）
record_url记录并返回请求 URL（用于验证路径转发）
full_events返回完整事件序列：task -> status -> artifact -> message
error返回 HTTP 500 错误
tool_call:list_agents调用 Host 的 list_agents 工具并返回结果
tool_call:send_to_agent调用 Host 的 send_to_agent 工具
tool_call:get_agent_info调用 Host 的 get_agent_info 工具
disconnect_mid_stream发送一个事件后断开连接
empty_response仅返回状态变更事件，无消息内容
delayed_start延迟启动（当前等同 echo）

启动 Fake Agent：

# 默认模式 (echo)，端口 10001
go run e2e/fake_agent/main.go

# 指定模式和端口
go run e2e/fake_agent/main.go -name my-agent
PORT=10002 go run e2e/fake_agent/main.go

10. Docker Compose 部署

平台提供了 Docker Compose 配置，可以一键启动完整的 A2A 平台（Host + 2 个 Fake Agent）。

10.1 文件位置

e2e/docker-compose.yml   # Compose 编排文件
e2e/Dockerfile.host      # Host 镜像构建文件
e2e/Dockerfile.agent     # Agent 镜像构建文件

10.2 快速启动

# 进入 e2e 目录
cd e2e

# 启动所有服务（后台运行）
docker-compose up -d

# 查看服务状态
docker-compose ps

# 查看日志
docker-compose logs -f host

10.3 服务编排

服务端口说明
host${HOST_PORT:-7860}:7860A2A Host 控制平面
fake-agent-a10001:10001测试 Agent A
fake-agent-b10002:10002测试 Agent B

10.4 自定义配置

# 使用自定义 Host 端口
HOST_PORT=9000 docker-compose up -d

# 停止所有服务
docker-compose down

# 停止并删除数据卷
docker-compose down -v

10.5 部署后验证

# 1. 检查 Host 运行状态
curl http://localhost:7860/api/capabilities

# 2. 注册 Agent A
curl -X POST http://localhost:7860/api/agents/register \
  -H "Content-Type: application/json" \
  -d '{"url": "http://host.docker.internal:10001"}'

# 3. 发送测试消息
curl -N -X POST http://localhost:7860/api/chat \
  -H "Content-Type: application/json" \
  -d '{"agent_name": "fake-agent", "message": "Hello from Docker!"}'
网络提示：在 Docker 容器内访问宿主机服务时，使用 host.docker.internal（Docker Desktop）或宿主机内网 IP。 Agent 容器间通信应使用 Docker 网络中的服务名。
